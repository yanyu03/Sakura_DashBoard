# SakuraEdu：面向学校组织关系的教学工作台

适合在简历项目链接、作品集说明或技术面试中使用的案例。以下描述对应本仓库的实现与证据；作者应根据自己能解释和维护的部分调整简历文字，不添加未经验证的性能提升、学校数量或商业落地经历。

## 30 秒介绍

SakuraEdu 是一个从界面原型逐步演进的全栈教学工作台。项目重点是把学校中的多级组织、教师兼任和任教资格映射到数据库与业务授权，形成“课表草稿 → 共享提交 → 负责人审批 → 正式课时”的闭环，并把原 SQLite 存储平移到 Cloudflare Workers 后的 TiDB。配套可本地复现的测试、增量迁移、凭据隔离和公开验证记录。

## 需求与作者工作范围

最初界面来自 Google Stitch / AI Studio。作者推动产品需求、1.0Sakura 设计标准、组织制度模型及业务迭代；实现中使用 AI 辅助编码、排障、验证与文档整理。项目主张是能解释需求、审查结果并维护工程，而不是宣称全部代码均由人工独立逐行完成。

作品范围包括单校教师 / 管理员业务、可配置组织关系、协同排课、SQLite → TiDB 迁移与边缘部署。没有把组织元数据中的家长 / 学生身份包装为已经交付的多端产品，也没有虚构真实学校运营数据。

## 三个值得展开的设计问题

### 1. 同一个人可以有多个岗位，但不能因兼任而得到所有数据

**问题**：A 是班主任，也是某学科组成员；B 是教研室负责人。B 需要知道 A 具备某课程的资格，但不应因此读取 A 的私人教案、其他班级学生记录或其他学校任职。

**方案**：分离账号、校内人员、带有效期的任职、实际任课与课程资格。授权取后台组织链和当前有效记录，而不是可编辑的“部门 / 职务”字符串；按校内人员去重并检查别名自审。

**代码与证据**：`server/organizationCore.ts`、`server/organization.ts`、[v15 实现](verification/organization/README.md)、[22 组本地场景](verification/organization/native.json)。

**取舍**：保留历史账号表以控制迁移范围，因此目前仍不是完整 IAM，也未解决全部历史公开资料的多学校边界。

### 2. 审批必须对当前事实负责，不能只相信提交时的快照

**问题**：教师提交时有任职，不代表审批时仍有效；两个负责人也可能同时批准重叠安排。申请本身不能直接成为正式课时。

**方案**：个人草稿默认不共享，提交明确选择教研室；审批时重新检查任职、任课、课程资格、教师 / 班级 / 教室时间冲突和记录版本。在事务内创建正式课时，拒绝自审与过期版本。

**代码与证据**：`server/scheduleSharing.ts`、`server/schedules.ts`、[17 组本地共享场景](verification/schedule-sharing/native.json)、[真实 Worker 组织排课](verification/tidb/api.json)。

**取舍**：待审批申请不预占课时，冲突在审批时最终判断；当前使用统一写协调保护约束，容量仍需另行优化和压测。

### 3. 数据库超时不能被处理成“自动重试一次就好了”

**问题**：一次 COMMIT 的确认丢失，不代表写入未发生。盲目重放可能重复发布、导入或审批；数据库短暂不可用也不应把用户强制退出。

**方案**：有界数据库超时，区分认证失败与临时 503；未知提交不自动重放，连接释放后允许新显式事务。密码采用加强 scrypt + 独立 pepper，凭据由 CF Secret 提供，日志不输出底层消息或 SQL 参数。

**代码与证据**：`server/tidb/database.ts`、`server/tidb/http.ts`、`server/passwords.ts`、[故障注入](verification/tidb/failures.json)、[安全专项](verification/security/hardening.json)、[6 项真实边缘检查](verification/security/cf-hardening.json)。

**取舍**：官方 HTTP 驱动的交互事务仍是实验能力；当前证据是功能与故障测试，不是容量或服务等级保证。

## 10 分钟面试演示建议

1. 用 [本地空库](GETTING-STARTED.md) 注册第一位管理员，解释为什么系统管理员与教研室负责人是两种权限。
2. 展示组织树和 A / B 场景，说明身份有效期、跨组隔离和目录去重。
3. 走一次草稿 / 提交 / 审批流程；展示无关用户拒绝、自审拒绝或旧版本 409。
4. 打开一项回归证据与其测试脚本，解释测试环境、夹具和它没有覆盖的范围。
5. 指出当前瓶颈与下一阶段：公开资料机构边界、周模板 / 校历、精确约束检查与恢复演练。

不要使用线上管理员密码、真实学生记录或作者的 TiDB 账户做面试演示。截图与离线运行已足以说明界面和流程。
