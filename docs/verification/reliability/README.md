# 注册登录与启动可靠性验证

2026-10-28，1.0Sakura。

## SQLite / HTTP

运行 `npm run test:reliability`。脚本为每次运行创建独立数据库，启动真实 Node 服务，并在进程外制造写锁、失败和重启。没有对业务数据库执行破坏测试。

11 项结果见 [auth-sqlite.json](auth-sqlite.json)，覆盖注册登录、并发重复注册、验证码重放、注册与会话写入失败、限速状态更新失败、短锁等待、长锁 503、进程重启持久化、注销持久化及关闭连接后的结构化错误。

修复：本地 SQLite 等锁上限 3 秒；不可用错误返回 503、`Retry-After: 3` 和 `Cache-Control: no-store`；成功认证的限速状态清理与账号/会话创建使用同一事务，提交后才响应成功。验证码仍按单次使用规则核销，登录失败后应获取新验证码。

关闭连接测试只验证显式重新打开后的恢复，不代表实现了自动重连。磁盘损坏、只读或空间不足仍需要运维修复，不能靠加载动画恢复。Cloudflare 使用 Durable Object SQLite，原生 `busy_timeout` 只适用于本地 better-sqlite3。

另外，注册回归 6 项、保护模块 9 项、本地 Workers 安全回归 5 项通过。安全回归证据位于相邻 auth/security 目录。
