# Sakura_DashBoard 业务完善计划

编制日期：2026-10-27。状态：首轮核心业务已在本地实现并验收；范围与遗留项见 [实施进度](BUSINESS-PROGRESS.md) 和 [验收记录](BUSINESS-ACCEPTANCE.md)。

## 目标与工作边界

把现有教师端草稿完善为可持久化、可验证的教务业务应用。一次操作要形成完整链路：页面输入 → 权限与校验 → 数据库事务 → 真实响应 → 页面刷新后仍一致。

以当前 React + Express + SQLite 为实施基础，沿用 1.0Sakura 视觉规范。先按单校、教师端应用推进，首轮使用管理员与教师两类权限，班主任权限由班级关联授予。家长端、学生端、多校租户、云部署与真实第三方登录不作为首轮完成的前提；后续可按需求扩展。

这是一组实施默认值，不表示这些能力已经实现。涉及学校实际评分规则、审批人或对外发送策略时，先把可配置规则与验收样例做实，再确定具体配置。

## 当前证据与缺口

- SQLite 测试已验证读写、事务、持久化与在线备份，21 项回归通过；见 [SQLite 实测报告](SQLITE-VERIFICATION.md)。
- 运行 DDL 没有外键、额外业务索引和版本化迁移；与文档 DDL 不一致。
- 登录返回的 token 是字符串示例；现有接口缺少统一会话校验。默认资料接口还包含密码字段，账号流程和验证码规则存在演示行为。
- 部分写入失败或服务离线时，业务层仍会回退成演示成功；某些界面先显示成功，再更新本地数组。
- 作业筛选不实际过滤，给不存在记录评分也返回成功；批阅状态与多处统计缺乏统一来源。
- 课表接口主要返回行数；调课申请直接写成 APPROVED，没有完整冲突与审批流程。
- 成绩图表、工作台卡片和 AI 结果存在固定数值；部分按钮仅显示 Toast。
- 家校留言虽有落盘接口，但学生档案中的消息、会话摘要、未读数和待办未形成一致模型。

## 固定实施顺序

每阶段单独形成可查看的本地改动与验收记录。前一阶段的关键约束通过后，再开始依赖它的下一阶段。

| 顺序 | 阶段 | 主要交付 | 完成标准 |
| --- | --- | --- | --- |
| 0 | 冻结基线与功能清单 | 当前数据库备份、功能/按钮/接口矩阵、现有用例基线 | 每项入口标为真实实现、演示、缺失或停用；原有本地数据可恢复 |
| 1 | 数据库与接口基础 | 版本化 SQLite 迁移、基础关联、公共错误与事务规则 | 旧库升级不丢业务数据；空库可初始化；数据约束与错误响应能自动验证 |
| 2 | 登录、会话与权限 | 真实账号会话、密码哈希、管理员/教师和班级范围 | 未登录返回 401；无权限返回 403；退出后会话失效；管理接口受限 |
| 3 | 学期、班级、学生与任教关系 | 主数据管理、统一 ID、名单查询与归档 | 至少两个教师、两个班级的隔离样例通过；搜索分页与刷新结果一致 |
| 4 | 作业发布与人工批阅 | 作业、提交、评分、印章、退回订正与统计 | 创建作业到批阅完成的闭环持久化；错误记录不报成功；并发修改不互相覆盖 |
| 5 | 教案库 | 新建、编辑、版本、标签、筛选与归档 | 保存后跨页面、刷新与重启可读；编辑冲突可识别；关联课时与作业可用 |
| 6 | 课表与调代课 | 真实课表行、教师/班级/教室冲突校验、审批状态机 | 提交申请不直接生效；审批通过才更新课表；冲突或失败时整个变更回滚 |
| 7 | 考试与成绩分析 | 考试、科目/题目得分、导入校验、真实统计 | 均分/分布/优秀率等与已知样本逐项吻合；缺考和未评分不被当作 0 分 |
| 8 | 家校与学生关怀 | 联系人、内部消息、会话、未读、家访待办与免打扰规则 | 消息与摘要同事务更新；档案和会话看到同一条数据；重复提交不重复生成 |
| 9 | 工作台、全局搜索与导出 | 聚合真实模块数据、权限内搜索、站内通知和实际文件 | 修改源数据后相关统计同步；搜索不再按关键词猜跳转；导出可下载并核对内容 |
| 10 | AI 与外部连接 | 可选任务服务、结果溯源、失败/重试与人工确认；按需接第三方 | 未配置时明确不可用；真实结果可追踪；AI 不直接覆盖教师最终评分 |
| 11 | 整体验收 | 迁移/权限/业务/E2E 回归、备份恢复、多屏与故障测试 | 关键用户故事逐条通过；功能矩阵无假成功；遗留限制逐项列明 |

## 阶段 0：冻结基线

1. 备份当前 `.local-data` 的有效 SQLite 快照，记录版本与可恢复性。
2. 建立七个业务页面及登录、设置、控制台的功能矩阵，覆盖每个可点击操作。
3. 固定现有 CSS/MD 与 SQLite 测试结果，建立不破坏现有视觉和持久化的基线。
4. 增加两个班级、不同任教范围的教师、多个作业与考试的隔离测试数据。预览数据、自动测试数据与真实使用数据分开。

交付：功能矩阵、待办编号和基线记录。此阶段先开展，不同时改造多个业务模块。

## 阶段 1：数据库与接口基础

- 确立唯一运行 schema，增加 schema_migrations；首次初始化、版本升级、演示数据填充各有独立入口。日常启动不因基准记录缺失而清空业务数据。
- 建立教师、学期、课程、班级、学生、任教与在班关系。资源关系统一用 ID，班级名称只作显示字段。
- 对现有库先备份、检查孤立数据，再用迁移补外键、唯一约束、必要 CHECK 与查询索引；历史异常进入明确修复清单，不能静默丢弃。
- 明确关系字段与 payload_json 的权威来源。评分、姓名、归属和状态等可查询业务字段以规范化表为准；JSON 仅保留适合的内容结构或快照，避免两份数据相互覆盖。
- 统一参数校验、404/409/422 等错误响应、分页、稳定排序、事务和操作审计。仅数据库提交成功后返回成功；发生响应丢失时不伪称操作绝未执行。
- 取消真实模式下全部业务写入的内存假成功。演示模式必须独立标识，不能伪装成持久化完成。
- 预留版本号、幂等请求标识及附件元数据模型。时间统一存储口径，显示按应用时区处理；原有本地时间数据迁移需记录解释规则。

验收样例：空库与旧库升级、重复升级、唯一键冲突、外键拒绝、事务中途异常回滚、资源不存在、服务离线。

## 阶段 2：登录、会话与权限

- 密码使用哈希；资料、错误提示与日志不返回密码。账号设置与个人界面偏好拆开，不能用“默认资料编辑”直接修改管理员身份与凭据。
- 建立服务端可验证、可撤销的会话，定义有效期、续期与退出；客户端渲染 workspace 不代表已经获得接口权限。
- 服务端从会话确认操作人、任教班级和资源范围，不能信任客户端传入的 teacherId。
- 验证码验证失败、过期、重复使用、缺失时按规则拒绝；演示答案提示与自动填充仅限显式演示环境。扫码、短信和 SSO 在未连接时显示未开通。
- SQLite SQL 执行、备份和恢复种子仅允许授权管理员；任意写 SQL 与种子重置默认限开发环境，普通教师看不到管理入口。
- 明确会话传输与 CSRF 防护规则，记录登录失败节流策略和审计脱敏。

验收样例：无密码、错密码、失效验证码、禁用用户、会话过期、退出后重放请求、跨班级访问、教师请求管理员端点。

## 阶段 3：主数据

- 实现学期、班级、学生和任教关系的创建、编辑、查询、归档。班级人数来自有效在班记录，不写死 45 人。
- 统一筛选、搜索、分页及空状态；归档关联数据时明确禁止、归档或保留历史的规则。
- 头像、学生标签和家长联系人先实现必要字段；禁止用姓名匹配作为跨模块关联依据。

完成此阶段后，后续模块不再自行维护一份互不一致的“班级名册”。

## 阶段 4：优先打通人工批阅

**第一条最小可用业务链：登录教师 → 选择任教班级 → 创建作业 → 录入/导入提交 → 人工评分 → 保存/下一份 → 班级统计更新 → 重启后复查。**

- 作业本身定义草稿、发布、截止、归档；学生提交沿用现有 pending、ai-pregraded、graded、needs-correction 状态，并明确每个允许操作。
- 订正重交保留历史，重新回到待处理状态；教师最终分数与 AI 建议分开存放。
- 校验成绩范围、作业满分、允许的小数精度、提交归属和操作权限；不存在记录返回 404。
- 评分、批注、印章新增与清除、优秀范文、退回订正均落盘。采用版本校验处理两个页面同时修改，冲突返回 409。
- “下一份”按筛选与排序定位；提交失败时保留输入，不提前跳走或改变统计。
- 待批数、提交率、均分、优秀率和分段统计来自真实数据；截止、未交、未评分、得分 0 分分别处理。

阶段 4 完成是第一个可用里程碑，后续模块可在此基础上逐步完善。

## 阶段 5—8：逐模块完善

### 教案

教案有作者、正文、单元、标签、状态、版本、可见范围与归档规则。保存内容要可重新打开编辑；引用统计与收藏只有存在记录时才展示。首轮按实际支持的文本/附件类型交付，不先承诺完整在线课件编辑器。

### 课表

接口返回实际课表行与时间范围，不只返回行数。冲突覆盖同一教师、班级、教室的时间重叠；审批期间再次检查，避免申请时无冲突、批准时已冲突。调代课按待审、通过、驳回、取消处理，跨教师的审批规则可配置。日历先提供真实 ICS 文件，外部日历同步延后。

### 考试与成绩

考试批次、考生、科目/题目满分与得分独立建模。导入先预览校验，再事务落库，重复导入有明确策略。统计口径区分缺考、缺失、未评分和零分；优秀/及格阈值可配置。学生轨迹来自历史考试，不能在切换考试后继续显示原图表。

### 家校与关怀

联系人、学生、会话与消息通过 ID 关联；发送内部消息与更新摘要/未读放在同一事务。学生档案的快捷留言与家校页共用同一服务，不能写死会话 ID。家访待办实现新增、完成、取消和到期查询。

首轮教师端支持站内记录与发送队列。未接家长端或外部服务时，只显示实际的“已保存/待发送”状态；“已送达/已读”必须有真实回执。免打扰作用于通知投递时间，不丢弃消息，也不伪造送达。

## 阶段 9：汇总与导出

- 工作台只聚合此前已完成的模块；今日课表、待批、未读与待办均受权限和时间范围限制。
- 全局搜索使用实际查询结果并携带正确资源 ID 跳转，支持无结果与无权限状态。
- 通知有真实事件、收件人、已读和去重记录。外部短信/邮件发送等待阶段 10 对接，不使用 Toast 充当送达回执。
- CSV、ICS、PDF 等导出按优先级逐个交付；下载文件内容、分页/全量范围和权限都验收，尚未实现的导出明确停用。

## 阶段 10：AI 与外部能力

人工流程稳定后再接入 OCR、批阅建议、教案建议和成绩解读。先确定提供方、凭据配置和数据发送范围，再实现服务端任务，不在前端保存密钥。

任务须有 queued/running/succeeded/failed/cancelled 等状态、输入版本、结果来源、超时与可控重试。重复点击不会重复生成或重复收费；失败保留人工流程。所有评分建议需教师确认，AI 不直接发布最终分数。

二维码登录、短信验证码、外部家校消息、日历和投屏设备分别作为明确适配任务；未配置时不宣称已连接。具体供应商选择与费用不在本轮计划中预设。

## 每阶段统一验收

1. 对涉及的新 schema 和旧库迁移运行隔离数据库测试，不用用户当前库作破坏性试验。
2. 覆盖成功、校验失败、无权限、记录不存在、重复请求、版本冲突和事务异常等适用分支。
3. 在浏览器执行该阶段的完整用户故事，刷新与重启后复查；需要更新跨模块展示时，验证它们来自同一条持久化记录。
4. 验证相关页面的手机布局、键盘焦点、加载/错误/空状态、暗色主题与减少动态效果。
5. 通过类型检查和构建；已有 SQLite 与 CSS 规范测试按变更维护，真实鉴权上线后调整测试登录流程，不新增跳过鉴权的测试后门。
6. 更新接口文档、功能矩阵和测试记录，标明真实实现与仍未连接能力；保留阶段恢复点。

## 完成里程碑

- **M1：阶段 0—4。** 可用的人工教师工作流：账号与权限、主数据、作业批阅、可靠持久化。
- **M2：阶段 5—9。** 七个主要模块共享真实数据，形成教学、课表、成绩、家校与工作台的业务联动。
- **M3：阶段 10—11。** 按实际选定范围接入外部能力，完成整体回归。未配置的外部服务保持明确不可用，不能靠假结果完成验收。

本文保留原定实施顺序。阶段 0—9 的首轮核心流程已执行；阶段 10 未配置的外部服务保持关闭，阶段 11 的本轮验收结果见 BUSINESS-ACCEPTANCE.md。
