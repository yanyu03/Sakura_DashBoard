# 业务功能回归：2026-10-29

本轮验证实际 Cloudflare Worker → TiDB HTTPS → API 返回结果的业务流程。新增、修改、异常尝试仅使用 `sakura_migration_functional_*` 独立库中的合成账号和教学资料。未导入用户提供的授课总表，未使用线上账号资料作为测试夹具。临时 Worker 使用额外随机密钥保护，测试结束后移除。

## 已发现并修复

| 问题 | 复现与处理 |
| --- | --- |
| 迁移后缺少兼容读取接口 | `GET /students`、`GET /homework/submissions` 未纳入公共应用，返回 404。提取为两种数据库共用的 `legacyViews.ts`，保留班级权限过滤；辅导记录仅查询当前可见学生。 |
| 空库首注册没有管理员 | 实际空库注册首位用户得到 teacher。改为在账户创建事务中检查是否空库，首位获得 admin 权限和“系统管理员”显示职务；已有账号的安装不重新提升权限。并发首次注册仅产生一位管理员。 |
| 成绩轨迹返回空对象 | 异步 `flatMap` 返回 Promise 数组，JSON 被序列化为 `{}`。改为等待各报告结果后展开，验证零分与缺考状态。 |
| 管理员读取他人私有教案 | 实测管理员列表可读他人 private 教案。删除角色绕过：正文、修改、修订、列表、搜索及统计按作者与公开范围判断；公开只授予读取，编辑与修订仍归作者。 |
| 同班教师读取未共享草稿 | 临时给予 B 与 A 同班任教后，B 能读取 A 的草稿。草稿详情、列表、搜索、旧批阅池和教案关联增加所有者限制；有效发布请求被拒绝，原状态与版本保持不变。 |

旧测试中的“直接创建正式课时成功”已不符合现行审批流程，现在验证该入口返回 409，再由组织/课表专用场景测试提交、共享和负责人审批。SQL 查询、备份及重置的 HTTP 管理入口继续禁止。

中文查询最初另有测试工具问题：curl 原样发送中文 URL，被入口返回无 JSON 的 400。验证工具改用 `new URL(...).href` 标准化编码后复测；该情况不计作数据库故障。测试过程出现的本地运维 MySQL TCP 超时，通过改用与 Worker 相同的 HTTPS 驱动完成复核；业务写入没有自动重试。

## 验证证据

- `functions.json`：22 组业务回归，包含真实注册登录、验证码重放/过期、CSRF、身份修改拒绝、跨班访问、学籍更新与版本冲突、作业发布/提交/零分/退回/重交/评分、教案修订/关联/归档、成绩预览/幂等导入/统计/轨迹、联系人/消息/未读/待办/辅导记录、工作台/搜索/通知、较大 JSON 响应和私有内容保护。部分场景修正工具编码后定向复测，最终报告按场景合并。
- `api.json`：9 组组织与现代排课场景，验证组织链、多岗、任教资格、无关人员阻断、资格撤销即时生效、课表草稿 → 提交 → 负责人审批 → 正式课时，以及退出会话。
- `first-registration.json`：空库首位管理员、后续注册不接受提权、并发注册仅一位管理员，共 3 项。
- 原生 SQLite 的注册 6、冷却 9、可靠性 11、迁移 7、组织 22、排课共享 17、身份层级 16，共 88 项回归通过；生产构建与两套类型检查通过。
- `../security/remote.json`：上线后真实域名的读取与认证冒烟。不会向生产创建合成学生、课程或课表。
- `functional-backup.json`：修复上线前，生产 58 张表的一致事务快照与原代码 bundle 已保存在 `.local-data/functional-release-backup/`，公开证据仅包含哈希和表数量。

## 复现

已配置操作者 TiDB 凭据与 Wrangler 登录后，依次运行：

```powershell
npx tsx scripts/prepare-tidb-functions.ts
npx tsx scripts/deploy-tidb-functions.ts
$env:SAKURA_VERIFY_CURL='true'
npx tsx scripts/verify-tidb-functions.ts
npx tsx scripts/deploy-tidb-functions.ts --cleanup
```

准备程序每次新建独立库并生成随机测试密码与入口密钥，私有目标配置保存在 `.local-data/functional-target.json`。切勿在运行中的测试期间重新生成目标。定向重跑可设置 `SAKURA_FUNCTIONAL_CASES` 为场景名前缀的逗号列表；它只适用于同一份已完成主要流程的夹具，并合并已有结果。完整复跑应新建夹具。Windows 的 `SAKURA_VERIFY_CURL` 是本地验证传输选项，生产 Worker 不依赖 curl。

## 本轮结论的边界

这是业务 API 回归，不是所有页面按钮的人工验收，也不是容量、长时间运行或灾难恢复演练。外部 AI/OCR 与家长消息实际投递保持停用，消息只验证入队与幂等，不能把 queued 当作已送达。

已发布的班级教学资料仍按任教范围协作，不能把当前实现描述成所有资料均按账号物理分库。私有教案与未共享草稿已有独立保护；`visibility=school` 的公开教案尚未建立机构归属，多个学校共用部署时需继续收紧公开范围。现行登录账户角色仍为 admin / teacher，家长、学生、辅导员等身份主要体现在组织元数据；这些身份的独立登录与业务授权不能据本轮结果宣称完成。

Key 报送的完整业务、周课表模板/单双周/校历、多机构公开内容边界及并发容量验收仍为后续工作；TiDB HTTPS 驱动交互事务仍处于官方实验阶段。当前结果不构成可大规模推广的验收结论。
