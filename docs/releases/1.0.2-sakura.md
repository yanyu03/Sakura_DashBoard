# 1.0.2-sakura · development branch

Application version: `1.0.2-sakura` · Design standard: `1.0Sakura` · API: `v1`.

## Changes

- Replace editable default class text with an authorized teaching-assignment relation.
- Introduce private scheduling tasks owned by an individual account, with a v16 SQLite migration and explicit TiDB DDL.
- Allow task titles and notes to be edited or cancelled directly in the scheduling workspace.
- Align version documentation and add version source consistency checks to CI, with feature-branch push checks.
- Keep real-world password recovery, complete role-based page flows and broader motion polish on the roadmap; they are not shipped in this patch.

## Deployment and acceptance

1. Create a verified backup before changing an existing TiDB database.
2. Apply `server/tidb/migrations/016-private-schedule-task-pool.sql` to the intended database before deploying v1.0.2.
3. Run `npm ci`, `npm run lint`, `npm run cf:check`, `npm run build`, `node scripts/verify-version-source.mjs`, `npm run test:local`, and `npm run test:security-hardening` on Windows.
4. Verify the private task pool with two separate accounts, expired assignments, cancellation, stale versions, and task-to-submission linking.
5. Deploy through a reviewed pull request only after CI and environment-specific migration checks; do not infer successful production deployment from a branch commit.

The checked-in test reports are historical evidence; this note does not assert that this new patch has passed CI or production testing.
