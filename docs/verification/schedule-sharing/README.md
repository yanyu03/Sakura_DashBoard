# 教研室课表提交与协同排课

2026-10-28，1.0Sakura，数据库增量迁移 v14。

## 使用顺序

1. 管理员打开“课表与排课 → 教研室与任职配置”，创建教研室，按不可修改的用户名核对账号，确认教师、教研室负责人（主任）的任职。已有组织中的上级主任任职可协调其下属教研室。
2. 管理员在基础资料中配置有效学期、课程、班级与任课关系。
3. 教师选择自己的任课班级、课程、时间与教室，保存个人草稿，或明确提交并共享到所属教研室。
4. 同室教师只读查看待审批和已通过的提交，负责人可批准或退回；教师可撤回待审批提交、修改后重新提交。
5. 审批通过后生成正式课时。正式课时可由任课教师调整共享范围；改期或代课仍走审批，负责人可取消自己负责范围内其他教师的课时。

第一位管理员不会自动获得所有私人草稿的读取权。若管理员兼任教研室负责人，须单独配置该任职；任何人均不能审批自己的提交。

## 权限边界

共享依据后台身份登记、组织 ID、有效任职和组织祖先链；不会按用户可编辑的部门名称、职务文字或前端传入的角色推断权限。教研室选项同时显示学校代码和教研室代码，区分同名组织。

个人草稿仅本人可见。待审批和已通过的提交向本室教师、导师、主任，以及组织上级的有效主任任职共享。退回与撤回记录仅本人及负责范围内的负责人可见，审批意见不向普通同事公开。共享范围只适用于课表，不扩大教案、学生资料等其他业务的权限。

任职撤销、到期、身份停用或组织归档会在下一次请求立即影响权限；权限缓存仅存在于单个 HTTP 请求内。旧课时不会自动公开，默认只向原任课教师显示，教师可主动共享。撤销正式课时共享时，关联的已通过提交同步停止共享；ICS 导出和工作台概览遵循相同规则。

提交人固定为当前登录账号，班级、课程和日期必须属于该账号的有效任课学期。审批时再次验证任职、任课关系，以及教师、班级、教室的时间冲突。多人同时审批使用版本号和事务保证只生成一个正式课时。待审批申请不预占时间，冲突在审批时作最终判断。

已审批提交保留当时的申请内容和原教研室归属。教师可将正式课时共享给自己另一个有效任职的教研室，此时仅共享正式课时，原提交与审批意见停止对其他人共享；恢复共享到原教研室时可恢复相应记录的可见性。后续正式课时的调代课、取消和共享变更以正式课表为准。列表每个日期范围最多展示 500 条提交，范围最长一年；大量记录可缩小日期范围查看。

本次仅建立排课共享的业务授权，不代表其他模块的完整多角色隔离已完成。
